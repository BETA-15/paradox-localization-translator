# Paradox Localization Translator v0.6.2

Paradox Interactive系ゲームのローカライズYAMLを、ローカルLLMまたはクラウドLLM APIで日本語化・修復・QAするGUIアプリです。

## 対応LLMプロバイダ

### ローカル
- **Ollama** — `http://localhost:11434`
- **LM Studio** — `http://localhost:1234/v1`

### クラウド
- **OpenAI** — `https://api.openai.com/v1`
- **Anthropic** — `https://api.anthropic.com/v1`
- **Google Gemini** — `https://generativelanguage.googleapis.com/v1beta`
- **OpenAI Compatible** — OpenAI互換 `/models` + `/chat/completions` APIを持つ任意サービス

GUIの「プロバイダ」から切り替えられます。

## APIキー

クラウドAPIではGUIの「APIキー」欄へ入力してください。入力欄はマスク表示されます。

**APIキーはアプリのセッション、モデルプロファイル、速度統計には保存しません。**
アプリを終了するとGUIに入力したキーは失われます。

環境変数も利用できます。

- OpenAI: `OPENAI_API_KEY`
- Anthropic: `ANTHROPIC_API_KEY`
- Gemini: `GEMINI_API_KEY` または `GOOGLE_API_KEY`
- OpenAI Compatible: `PLT_API_KEY`（未設定時は `OPENAI_API_KEY` も参照）

## v0.5.1 の追加機能

- **OpenAI API対応** — Responses APIを使用
- **Anthropic API対応** — Messages APIを使用
- **Gemini API対応** — `generateContent` APIを使用
- **OpenAI互換クラウドAPI対応** — URL + APIキーを任意指定
- **クラウドモデル一覧取得** — 各APIのモデル一覧からGUIへ読み込み
- **クラウドモデルも速度比較可能** — 平均秒、tokens/s（APIがトークン数を返す場合）、失敗率を記録
- **APIキー非保存** — 秘密情報をセッション/プロファイルJSONへ書き込まない
- **環境変数APIキー対応**

## クラウドAPIの使い方

1. 「プロバイダ」で OpenAI / Anthropic / Gemini / OpenAI Compatible のいずれかを選択します。
2. 通常は自動入力されたURLをそのまま使用します。
3. 「APIキー」へキーを入力します（環境変数を設定済みなら空欄でも可）。
4. 「接続確認 / モデル再読込」を押します。
5. モデルを選択します。
6. 翻訳キューを追加して「翻訳開始」を押します。

OpenAI CompatibleではAPIサービスのベースURLを手動指定してください。通常は `/v1` を含むURLを指定します。

## モデル統計

実際の翻訳と速度テストの結果を `.paradox_localization_translator/model_stats.json` に保存します。
APIキーは保存されません。

- Ollama: `eval_count / eval_duration`
- OpenAI互換 / LM Studio: `usage.completion_tokens`
- OpenAI: `usage.output_tokens`
- Anthropic: `usage.output_tokens`
- Gemini: `usageMetadata.candidatesTokenCount`

トークン数が返らない場合でも、平均処理時間と失敗率は記録します。

## スタンドアロンビルド

GitHub Actions の **Build standalone apps** を実行すると、macOS / Windows / Linux のスタンドアロン成果物を生成します。
Pythonを利用者側へインストールする必要はありません。

## v0.5.1 出力先と内蔵説明書

- 翻訳結果・セッション・用語集・モデル統計などの自動生成ファイルは、原則としてアプリ/実行ファイルの隣に `ParadoxLocalizationTranslator_Data` を作って保存します。
- アプリの隣へ書き込めない場合（例: macOSの `/Applications`）は、`Documents/Paradox Localization Translator` を自動利用します。
- 翻訳結果はその中の `翻訳結果`、設定類は `設定` に分けて保存します。
- 「選択項目の出力先変更」は、キュー内の対象行を選んでから使う個別変更ボタンです。未選択時には案内を表示します。
- GUI内に「使い方」タブを追加し、基本操作・出力先・中断再開・QA・各LLM接続方法をアプリ単体で確認できます。

## v0.5.5

### ドラッグ＆ドロップ

- YAMLファイルを「翻訳 / キュー」へ直接ドラッグ＆ドロップして追加できます。
- localization / Modフォルダのドラッグ＆ドロップにも対応します。
- 複数ファイルをまとめてドロップできます。
- スタンドアロン版には `tkinterdnd2` / TkDND を内蔵するため、利用者側で追加インストールは不要です。

### 翻訳ごとの独立キャッシュ

各キュー項目は専用の `translate_cache.json` を持ちます。キャッシュは次の場所へ保存されます。

- アプリの隣へ保存できる場合: `ParadoxLocalizationTranslator_Data/キャッシュ/`
- 書き込み不可の場合: `Documents/Paradox Localization Translator/キャッシュ/`

フォルダ名には開始日時・入力名・短いIDを含めるため、複数Modや別翻訳のキャッシュが混ざりません。保存して中断したセッションを復元した場合は、同じ専用キャッシュを引き続き使用します。

### キャッシュ管理

- **キャッシュを見る**: キューで選択した翻訳のキャッシュ件数・保存先・JSON内容を確認できます。
- **キャッシュを追加**: 既存の `translate_cache.json` を選択中の翻訳へ統合できます。
- 同じキーが存在する場合、取り込む側で上書きするか、既存値を優先するか選択できます。
- v0.5.4以前の `出力/.cache/translate_cache.json` が見つかった場合は、新形式の専用キャッシュへ自動引き継ぎを試みます。


## v0.5.6

### Mod更新時の差分追加翻訳

- 翻訳完了時に、原文YAMLのファイル・キー・原文ハッシュを `source_manifest.json` として各専用キャッシュへ保存します。
- 同じMod / localizationフォルダを後から再度キューへ追加すると、入力パスから過去のキャッシュを自動特定します。
- 前回スナップショットと現在の原文を比較し、**新規キー / 文章が変更されたキー / 削除キー / 新規ファイル / 削除ファイル**を判定します。
- 差分がある場合、前回キャッシュを新しい翻訳ジョブ専用キャッシュへ複製します。キャッシュを共有せず「翻訳ごとに分離」した構造は維持されます。
- 変更されていない文章は複製したキャッシュから復元し、**新規・変更箇所だけLLMへ送信**します。
- 新しく追加されたYAMLファイルは、そのファイル内のキーだけが新規翻訳対象になります。
- キューの状態欄に `差分 +12 / 変更3` のように表示します。
- `差分更新を再検出` ボタンで、選択中の翻訳について過去キャッシュと差分を手動で再判定できます。
- 差分内容は新しいキャッシュフォルダの `diff_report.json` に保存します。
- v0.5.6以降で一度通常翻訳した入力は、次回更新から自動差分判定できます。旧版キャッシュだけでは原文スナップショットが無いため、新規/変更の厳密な区別はできません。


## v0.6.0 — 未翻訳常時監視

### ゲーム本体 / Mod の未翻訳監視

「未翻訳監視」タブを追加しました。ゲーム本体やModの `localization` フォルダを指定すると、次の候補を一覧化します。

- 英語ローカライズは存在するが日本語ファイルがない
- 日本語ファイルは存在するが対応キーがない
- 日本語値が英語原文と同一のまま残っている
- 日本語ファイルに外国語だけの文章が残っている

### 軽量な常時監視方式

監視中にLLMを常時実行することはありません。通常時はYAMLファイルの更新時刻とサイズだけを確認し、変化がなければ本文解析もLLM呼び出しも行いません。

更新を検知した場合のみローカライズ全体を再解析します。さらに「固有名詞の英語表記なのか、未翻訳UIなのか」のような曖昧候補だけを、指定した監視用の軽量LLMへ最大40件ずつまとめて問い合わせます。日本語ファイル/キーそのものが欠落している候補は機械的に確定できるためLLMへ送りません。

監視間隔は3〜600秒で設定可能です。通常は10〜30秒程度を推奨します。

### 監視用LLM

翻訳本番モデルとは別に「監視用LLM」を指定できます。同じプロバイダのモデル一覧から、3B〜8B級などの軽量モデルを選ぶことを想定しています。

監視中にLLM判定が走る場合は、従来の上部LLM状態バーにも「未翻訳監視」と表示されます。監視停止、現在LLM処理の停止、今すぐ再スキャンに対応しています。

### 候補リスト

検出結果は「種類 / 判定 / ファイル / キー / 内容」で一覧表示され、CSVへ保存できます。英訳しかないゲームでは日本語ファイル欠落として大量のキーを一括リスト化できます。

## v0.6.2

### 未翻訳調査を自動翻訳から完全分離

- 未翻訳監視/調査は**自動翻訳を行いません**。YAMLの書換えもしません。
- 通常翻訳とは別に、監視専用の **プロバイダ / API URL / モデル / APIキー** を指定できます。
- 監視LLMは曖昧な短文だけを判定するため、GUIに **3B～8B級など小さなモデルを推奨**する警告を表示します。
- 「指定したModをバックグラウンド調査」を追加しました。
- 「全部のModを調べる」を追加しました。Mod親フォルダの直下から `localization/` を持つModを検出します。
- 調査はバックグラウンドスレッドで実行し、途中停止できます。
- 新しい **「翻訳状況」タブ**を追加しました。
  - `〇〇というModは日本語翻訳がありません。`
  - `〇〇のModに翻訳の欠損箇所があります（N件）。`
  - `〇〇のModは日本語翻訳が確認できました。`
  のようにMod単位で一覧表示します。
- `descriptor.mod` の `name="..."` があればMod名として使用し、無ければフォルダ名を使います。
- 翻訳状況一覧はCSVへ保存できます。


## v0.6.2: 翻訳状況から直接翻訳・Modへ上書き

- 「翻訳状況」タブでModを選び、その場で翻訳を開始できます。ユーザーがlocalizationファイルを別フォルダへ移動する必要はありません。
- 「選択Modを翻訳キューへ追加」で、調査結果から直接翻訳キューへ登録できます。
- 翻訳完了後、「完成した日本語化をModへ上書き」で生成済み日本語YAMLを元Modへコピーできます。
- 直接上書きは二重確認を行い、既存ファイルは `ParadoxLocalizationTranslator_Data/バックアップ/` へ自動バックアップしてから置き換えます。
- Steam Workshop等によるMod更新で直接上書き内容が失われる場合があるため、警告を表示します。
