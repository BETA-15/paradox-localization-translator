- アプリ内の **「使い方」タブを大幅拡充**し、初回セットアップから通常翻訳、QA、差分調査、検索修正、Mod調査、日本語化Modへの差分反映、キャッシュ、バックアップ、診断まで詳しく説明します。

## v0.7.5 バッチ・並列おすすめ設定

### バッチ / 並列おすすめ設定

GUIに3種類の設定プリセットを追加しました。

| プリセット | バッチ | 並列 | 用途 |
|---|---:|---:|---|
| 安定重視 | 20 | 1 | 長文Mod・初回利用・メモリ余裕が少ない環境 |
| 標準 | 40 | 1 | 通常推奨 |
| 高速 | 60 | 2 | サーバー側で2並列処理でき、RAM/VRAMに余裕がある環境 |

安定性の目安として、バッチ80超は注意、120超は非推奨です。ローカルLLMでは並列3以上になると、VRAM/RAM圧迫、リクエスト待ち、タイムアウトが増えやすくなります。数値は絶対的な上限ではなく、モデルサイズ・1行の長さ・コンテキスト・サーバー設定によって変わります。クラウドAPIでは各サービスのレート制限を優先してください。


- 残り時間予測表示を削除しました。
- 翻訳中は、キュー番号・ファイル番号・処理済み行数/総行数のみ表示します。
- 不安定な推定値を表示せず、実際の進捗だけを表示します。

## v0.6.6: 自動生成ファイルの保存先を統一

アプリが自動生成するデータをすべて **`Paradox Localization Translator`** フォルダにまとめます。既定位置は `Documents/Paradox Localization Translator` です。

```text
Paradox Localization Translator/
├── 翻訳結果/
├── キャッシュ/
├── バックアップ/
├── ログ/
└── 設定/
    ├── session.json
    ├── glossary.json
    ├── model_stats.json
    ├── model_profiles.json
    └── steam_library_roots.json
```

GUIの **設定** タブから保存場所を変更できます。別ドライブ・外付けSSD・任意フォルダを選択可能で、既存データを新しい場所へコピーしてから切り替えることもできます。

Paradox Interactive系ゲームのローカライズYAMLを、ローカルLLMまたはクラウドLLM APIで日本語化・修復・QAするGUIアプリです。

## APIキー

クラウドAPIではGUIの「APIキー」欄へ入力してください。入力欄はマスク表示されます。

**APIキーはアプリのセッション、モデルプロファイル、速度統計には保存しません。**
アプリを終了するとGUIに入力したキーは失われます。

環境変数も利用できます。

- OpenAI: `OPENAI_API_KEY`
- Anthropic: `ANTHROPIC_API_KEY`
- Gemini: `GEMINI_API_KEY` または `GOOGLE_API_KEY`
- OpenAI Compatible: `PLT_API_KEY`（未設定時は `OPENAI_API_KEY` も参照）

## クラウドAPIの使い方

1. 「プロバイダ」で OpenAI / Anthropic / Gemini / OpenAI Compatible のいずれかを選択します。
2. 通常は自動入力されたURLをそのまま使用します。
3. 「APIキー」へキーを入力します（環境変数を設定済みなら空欄でも可）。
4. 「接続確認 / モデル再読込」を押します。
5. モデルを選択します。
6. 翻訳キューを追加して「翻訳開始」を押します。

OpenAI CompatibleではAPIサービスのベースURLを手動指定してください。通常は `/v1` を含むURLを指定します。

## モデル統計

実際の翻訳と速度テストの結果を `.paradox_localization_translator/model_stats.json` に保存します。
APIキーは保存されません。

- Ollama: `eval_count / eval_duration`
- OpenAI互換 / LM Studio: `usage.completion_tokens`
- OpenAI: `usage.output_tokens`
- Anthropic: `usage.output_tokens`
- Gemini: `usageMetadata.candidatesTokenCount`

トークン数が返らない場合でも、平均処理時間と失敗率は記録します。

## v0.5.6

### Mod更新時の差分追加翻訳

- 翻訳完了時に、原文YAMLのファイル・キー・原文ハッシュを `source_manifest.json` として各専用キャッシュへ保存します。
- 同じMod / localizationフォルダを後から再度キューへ追加すると、入力パスから過去のキャッシュを自動特定します。
- 前回スナップショットと現在の原文を比較し、**新規キー / 文章が変更されたキー / 削除キー / 新規ファイル / 削除ファイル**を判定します。
- 差分がある場合、前回キャッシュを新しい翻訳ジョブ専用キャッシュへ複製します。キャッシュを共有せず「翻訳ごとに分離」した構造は維持されます。
- 変更されていない文章は複製したキャッシュから復元し、**新規・変更箇所だけLLMへ送信**します。
- 新しく追加されたYAMLファイルは、そのファイル内のキーだけが新規翻訳対象になります。
- キューの状態欄に `差分 +12 / 変更3` のように表示します。
- `差分更新を再検出` ボタンで、選択中の翻訳について過去キャッシュと差分を手動で再判定できます。
- 差分内容は新しいキャッシュフォルダの `diff_report.json` に保存します。
- v0.5.6以降で一度通常翻訳した入力は、次回更新から自動差分判定できます。旧版キャッシュだけでは原文スナップショットが無いため、新規/変更の厳密な区別はできません。


## v0.6.0 — 未翻訳常時監視

### ゲーム本体 / Mod の未翻訳監視

「未翻訳監視」タブを追加しました。ゲーム本体やModの `localization` フォルダを指定すると、次の候補を一覧化します。

- 英語ローカライズは存在するが日本語ファイルがない
- 日本語ファイルは存在するが対応キーがない
- 日本語値が英語原文と同一のまま残っている
- 日本語ファイルに外国語だけの文章が残っている

### 軽量な常時監視方式

監視中にLLMを常時実行することはありません。通常時はYAMLファイルの更新時刻とサイズだけを確認し、変化がなければ本文解析もLLM呼び出しも行いません。

更新を検知した場合のみローカライズ全体を再解析します。さらに「固有名詞の英語表記なのか、未翻訳UIなのか」のような曖昧候補だけを、指定した監視用の軽量LLMへ最大40件ずつまとめて問い合わせます。日本語ファイル/キーそのものが欠落している候補は機械的に確定できるためLLMへ送りません。

監視間隔は3〜600秒で設定可能です。通常は10〜30秒程度を推奨します。

### 監視用LLM

翻訳本番モデルとは別に「監視用LLM」を指定できます。同じプロバイダのモデル一覧から、3B〜8B級などの軽量モデルを選ぶことを想定しています。

監視中にLLM判定が走る場合は、従来の上部LLM状態バーにも「未翻訳監視」と表示されます。監視停止、現在LLM処理の停止、今すぐ再スキャンに対応しています。

### 候補リスト

検出結果は「種類 / 判定 / ファイル / キー / 内容」で一覧表示され、CSVへ保存できます。英訳しかないゲームでは日本語ファイル欠落として大量のキーを一括リスト化できます。

## v0.6.6: 別ドライブ・外付けSSDのSteamライブラリ検出

ゲームやSteamライブラリがOSの標準ドライブ以外にある場合にもMod場所を自動検出できるようにしました。

- Windows: C: 以外の利用可能なドライブも浅く探索し、`Steam` / `SteamLibrary` / `Games/Steam` などと、直下に `steamapps` を持つカスタム名のライブラリを検出します。
- macOS: `/Volumes` 配下の別ボリューム・外付けSSDを浅く探索します。
- Linux: `/mnt` / `/media` / `/run/media` のマウント先を浅く探索します。
- Steamの `libraryfolders.vdf` から登録済み追加ライブラリを引き続き取得します。
- 一度検出したSteamライブラリは `設定/steam_library_roots.json` に記録し、次回の自動探索でも再利用します。
- 全ドライブを再帰的に総当たりする方式ではなく、Steamライブラリらしい場所だけを浅く確認するため、大容量SSDでも探索負荷を抑えています。

## v0.6.7: 選択Modを除外して一括翻訳

「翻訳状況」タブに **選択Modを除外して翻訳** を追加しました。

- Ctrlキーを押しながら、除外したいModを複数選択できます。
- 選択したModは翻訳対象から外し、それ以外で「翻訳なし」「欠損あり」と判定されたModを一括で翻訳キューへ追加します。
- 「翻訳あり」で欠損0件のModは、選択状態に関係なく不要な再翻訳を避けるため自動的に対象外にします。
- 実行前に、除外件数・翻訳対象件数・除外Mod名を確認するダイアログを表示します。
- すでに翻訳処理中の場合はキュー末尾へ追加し、現在の処理完了後に続けて翻訳します。


## v0.7.0 追加機能

- LLM状態表示を2段に分離
  - 翻訳用LLM
  - 未翻訳Mod探索用LLM / Mod調査
- バックグラウンド調査中は、現在調査中のMod名と進捗を常時表示
- 元Mod内の日本語化だけでなく、別の日本語化Modもキー重複から自動検出
- 翻訳状況で次を区別
  - 日本語翻訳なし・日本語化Modなし
  - 別Modに完全な日本語化あり
  - 別の日本語化Modあり・欠損あり
  - 元Mod内に完全な日本語化あり
- 翻訳状況一覧に「日本語化Mod」「日本語化Mod欠損」列を追加
- 別日本語化Modが不完全な場合、翻訳後の差分上書きは元Modではなく日本語化Mod側へ実施
  - 既存訳は維持
  - 未翻訳/欠損キーだけ更新
  - 存在しないキーは専用差分YAMLへ追加
  - 変更前ファイルは自動バックアップ

### 別日本語化Modの検出について

Workshopフォルダ名やMod名だけには依存せず、元Modの英語/中国語ローカライズキーと、別Modの日本語ローカライズキーの一致率を中心に判定します。名前が近い場合は補助情報として利用します。誤検出を避けるため、キーの一致が少ないModは日本語化Modとして扱いません。
